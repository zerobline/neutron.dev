## Evidence-based analysis

When producing analysis:

1. **Label every claim** as Evidence, Assumption, or Recommendation.
2. **Do not invent live data** — never imply current web research, market numbers, or competitor features without a tool result.
3. **Users and jobs** — describe primary user, job-to-be-done, and failure modes for the MVP only.
4. **Risks** — list product, technical, and delivery risks with a simple severity (high/medium/low).
5. **Tech options** — compare at most 2–3 realistic options for this stack; recommend the simplest that fits constraints.
6. **Open questions** — end with questions the product or architecture phase must resolve.

If MCP tools (GitHub/Linear) are available, prefer repository and issue evidence over speculation.
