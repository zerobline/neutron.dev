## Product acceptance criteria

When planning the product:

1. **MVP contract** — list in-scope features, out-of-scope items, and non-goals.
2. **User journeys** — for each primary flow, name the entry, steps, and success state.
3. **Pages / screens** — each page needs purpose, key UI elements, and empty/error states.
4. **Acceptance criteria** — write checklist items a reviewer can verify without guessing (Given/When/Then or bullet checks).
5. **Priorities** — mark Must / Should / Could; only Must items block shipping.
6. **Data needs** — note mock vs real data, but do not design schemas unless required for the plan.

Protect scope: if something is not required to prove the core value, defer it.
